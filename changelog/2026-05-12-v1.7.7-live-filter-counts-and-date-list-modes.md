Version 1.7.7 makes calendar filter counts reflect what is actually on screen, and adds two new list modes to the Event Occurrences element and the `{lre_occurrences}` tag.

<!-- truncate -->

---

## Live, view-aware filter counts

Counts on calendar filters now show the number of event occurrences in the visible calendar range, and update as you move between months. This applies to all three calendar filters:

- the `[lre_calendar_filter]` shortcode
- the inline filter in `[lre_calendar]` (the `filter="..."` attribute)
- the Native Filter group on the LRE Calendar element in Bricks

Previously a term's count was the number of event posts assigned to it, whatever month was showing.

While a filter is selected, the other options keep showing what they would reveal if clicked, so visitors can see which categories have events in range before choosing.

### Keeping the old counts

Existing set-ups with counts switched on start showing the new counts after updating. To keep total post counts, for example on a directory page:

```
[lre_calendar_filter count_mode="total"]
[lre_calendar filter_count_mode="total"]
```

In Bricks, use the new **Count Mode** control in the Native Filter group.

In the new mode every term in the taxonomy is shown, including terms with no events, so that each can pick up a count as the calendar moves. `hide_empty` applies to the `total` mode only.

## Show Which Dates

The LRE Event Occurrences element has a new **Show Which Dates** control with three modes:

| Mode | Lists |
| --- | --- |
| **Upcoming dates** | Future dates from today. The default, and the previous behaviour |
| **Next dates after the one being viewed** | Dates after the occurrence in the page address. Useful for a "what's next" section on a single event page |
| **All other dates** | Every date of the event except the one being viewed, including past dates |

The `{lre_occurrences}` tag accepts the same modes after the limit:

```
{lre_occurrences:5:next_after_current}
{lre_occurrences:5:all_others}
```

`{lre_occurrences}` and `{lre_occurrences:5}` behave as before.

The old **Exclude Current Occurrence** checkbox has been folded into this control. Elements that had it switched on now use "Next dates after the one being viewed", so nothing changes on your pages.

When a list is empty and you have not set your own Empty Message, the fallback text now matches the mode: "No upcoming dates", "No further dates" or "No other dates".

## For developers

Each event in the calendar events response now carries its taxonomy terms in `extendedProps.taxonomies`, a map of taxonomy slug to term slugs. This is what powers the new counts.

## Fixed

- **Year view dots sit directly under their date.** They were anchored to the bottom of each day cell, which left a gap and made them look closer to the row below.
- **Today no longer makes its row taller in the year view.** Today's highlight is now the same height as a normal day number.
- **Changing an event's terms outside the editor now refreshes the calendar.** Quick Edit and programmatic term changes could leave old term data in calendar responses for up to five minutes.

## Improved

- **Dots sit closer to the date number on tablets and phones**, so the month grid takes less vertical space.
